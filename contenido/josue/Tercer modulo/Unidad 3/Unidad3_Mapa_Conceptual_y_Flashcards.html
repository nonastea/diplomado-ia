Diez puntos donde el material del curso se queda corto, está desactualizado o simplifica lo que dice la fuente. Dominar ambas versiones te cubre cualquier variante de pregunta en el examen.

01 ¿Elimina o reduce alucinaciones?

Curso: el caso dice que la política de incertidumbre «eliminó las alucinaciones»; el video, que las ocho piezas son «para evitar alucinaciones». Evidencia: Anthropic dice que estas técnicas las reducen significativamente, no las eliminan; OWASP: ningún método es infalible.

Regla: si preguntan qué logró el prompt en el caso Horizonte, responde lo que dice el curso (trazabilidad, política de incertidumbre, sin alucinaciones); si preguntan en general, di «reduce» y que siempre se requiere verificación humana.

02 Rey − Hombre + Mujer y «siguiente palabra».

Curso: la figura del Transformer ilustra embeddings con esa analogía y habla de predecir la siguiente palabra. Evidencia: la analogía viene de word2vec (2013, embeddings estáticos); el Transformer produce embeddings contextuales (justamente el paso 2 de la figura); el modelo predice el siguiente token.

Regla: en el examen respeta los 4 pasos y sus nombres; si preguntan qué unidad predice el modelo, «token» es lo más preciso.

03 SynthID no es universal.

Curso: lo pone como parte de la fase de generación de respuestas del ciclo de vida. Evidencia: es la marca de agua de Google DeepMind para contenido de su IA; otros proveedores usan otros mecanismos o ninguno.

Regla: si preguntan por SynthID, define marca de agua imperceptible para identificar contenido generado por IA (de Google); no afirmes que todo LLM la aplica.

04 El rol «aporta poco».

Curso: asignar un rol aporta poco si faltan problema, audiencia, fuentes y criterios. Evidencia: Anthropic recomienda asignar un rol en el prompt de sistema (incluso una frase ayuda). No se contradicen: el rol es útil y barato, pero no sustituye las piezas.

Regla: el rol orienta vocabulario y perspectiva; no reemplaza resultado, contexto, insumos y criterios.

05 «Mayor prioridad» del mensaje de sistema.

Curso: instrucción de mayor prioridad. Evidencia: es una jerarquía entrenada (OpenAI Model Spec: plataforma > desarrollador > usuario), no una garantía técnica; por eso existe la inyección de prompts.

Regla: responde la definición del curso; si la pregunta es de seguridad, agrega que la prioridad no blinda contra inyección.

06 Los atajos «/promptsistema» no son comandos nativos.

Curso: lista «/promptsistema + /(objetivo) + /(formatodesalida)» como atajo. Evidencia: las API de LLM solo conocen roles de mensaje (sistema, usuario, asistente); el «/» es una convención de interfaz o un acuerdo dentro del prompt, que funciona si el modelo entiende la intención o si fue definida en un GPT/proyecto personalizado [inferencia, sin fuente primaria].

Regla: trátalo como plantilla de metaprompting, no como función del modelo.

07 JSON vs Markdown y la validación.

Curso: JSON requiere validación antes de alimentar otro sistema, «al igual que los markdown (.md)». Evidencia: JSON es un formato de máquina con esquema validable (Structured Outputs garantiza el esquema; el JSON mode solo la sintaxis); Markdown es un formato de presentación sin esquema estricto: se revisa, pero no se valida igual.

Regla: toda salida estructurada se valida; JSON con esquema y parser, Markdown con revisión de estructura y contenido.

08 Pre-entrenamiento con «datos públicos filtrados».

Curso: grandes volúmenes de datos públicos filtrados. Evidencia: los proveedores también usan datos licenciados y propios (Llama 4: mezcla de datos públicos, licenciados y de productos de Meta).

Regla: responde «grandes volúmenes de datos filtrados por calidad y seguridad» y, si cabe, menciona que no son solo públicos.
